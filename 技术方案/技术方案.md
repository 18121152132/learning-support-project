# 学习支持与辅导协作智能体系统 · 技术方案

版本：`pilot-v1` / 知识图谱 `kg-v1`　｜　更新日期：2026-11-12　｜　对应黑板流程 ①—⑤ 与 `docs` 交付物

## 1. 系统定位与边界

- 北辰在线学院「学习掉队以后才收到提醒」合成训练案例，首期只做**求助归集、连续求助识别、交接单五要素校验、附行为证据的支持建议**。
- AI 只做识别与提示：不自动联系学生、不给学生定性/评分/处分、不覆盖原始业务记录；所有对外动作必须人工确认。
- 只读接入群聊、作业评论与 LMS 学习事件；当前使用合成只读样本源，接口中断时降级为带时间戳的只读快照并标注「暂未更新」。
- 试点范围：两个班级、一个助教小组；基线数字（26h / 35% / 每周约 900 条）未逐笔验证前不写入验收结论。

## 2. 技术栈（严格按黑板，不替换、不引入未要求中间件）

| 编号 | 黑板要求 | 落地选型 | 说明 |
| --- | --- | --- | --- |
| ① | FastAPI | FastAPI 0.162.5 | 对外接口层 `app/api.py`，异常处理器统一收口 404/405/422/500 |
| ② | Python 3.11+ | Python 3.13.14 | `server.py` 启动时按 `runtime.python_min_major/minor` 校验，低于 3.11 拒启 |
| ③ | Harness | 自研 `harness/` 运行壳 | 逐用例隔离、动作白名单、确定性断言、历史回放、CLI 与报告；零第三方 harness 框架 |
| ④ | 知识库（知识图谱） | 本地 JSON 图 `data/knowledge/graph.json` | 纯标准库构建/查询，**不引入图数据库、向量库、缓存或消息队列** |
| ⑤ | 本地部署（例：Ollama） | 本机 Ollama + `qwen3.5:4b` | 地址、模型名、健康地址、超时、think 开关全在 `config.yaml`；本地无需密钥 |

- 运行依赖仅 `requirements.txt` 两项：`fastapi>=0.110,<1.0`、`uvicorn>=0.27,<1.0`。
- 其余模块（配置解析、存储、审计、权限、安全审查、知识图谱、harness）全部使用 Python 标准库。
- ASGI 服务器为 `uvicorn`（FastAPI 运行所需，非中间件）；`server.py` 校验 `asgi.server`，非 uvicorn 直接拒启。

## 3. 架构分层

```
config.yaml ── 唯一配置（模型地址/模型名/阈值/角色/红线/知识库/提示词路径）
      │
      ├─ 契约层      response.py（统一返回）  config_loader.py（YAML 子集解析）
      ├─ 门禁层      rbac.py  security.py  confirmation.py  stop.py  audit.py
      ├─ 业务层      ingest → identify → handoff → advisor → confirmation → service.py
      ├─ 知识层      knowledge.py ← data/knowledge/graph.json ← scripts/build_knowledge.py
      ├─ 模型层      advisor.py → Ollama /api/generate（本地，可关闭）
      ├─ 接口层      api.py（FastAPI）→ server.py（uvicorn）
      └─ 运行壳      harness/（cases / gates / core / replay / cli）
```

- 状态由 append-only 事件日志重放得出（`service.replay()`），错误结果不覆盖原记录。
- 所有对外响应恒为 `{"ok": bool, "data": ..., "error": {"code": str, "msg": str}}`；业务失败 HTTP 仍为 200，契约靠 `ok` 字段。

## 6. 数据红线落地

| 红线 | 实现 | 位置 |
| --- | --- | --- |
| 不依据敏感属性判断能力 | 键名黑名单 + 模型输出文本级禁止词扫描，命中即 `SENSITIVE_ATTRIBUTE` 并触发停止条件 | `security.py` / `advisor.py` |
| 每条建议附实际行为证据 | `fact_refs` 必含 `source_ref/event_time/channel`；知识库引用单独放 `knowledge_refs`，**不得写入 `fact_refs`** | `security.py` / `knowledge.py` |
| 禁止自动定性、评分、处分 | `banned_outputs` 字段黑名单；`forbidden_auto_actions` 拦截系统角色 | `security.py` / `rbac.py` |
| AI 不直接触达学生 | 建议挂起 → 接手确认 → 本人人工确认 → 才可联系；重复联系幂等 | `confirmation.py` |
| 错误结果不覆盖原记录 | append-only 事件日志；建议只追加 `SUGGESTION_PENDING` | `store.py` / `audit.py` |
| 越权拦截并留痕 | `_guard` 三层门禁（权限 / 自动动作 / 本人签核），拒绝时写 `denied` 审计 | `service.py` |
| 脏数据不进自动样本 | 缺编号/时间/版本、补交撤回进修复队列，人工确认后回流 | `ingest.py` / `security.py` |
| 停止条件即暂停 | 暂停 → 顾明岚复盘 → 傅景判定恢复 | `stop.py` |
| 审计可重建 | 业务编号、资料版本、事实引用、建议结果、人工改动、签核人 | `audit.py` |
| 知识库只读 | 无写图谱接口；构建只由离线脚本完成 | `knowledge.py` / `build_knowledge.py` |

## 7. ④ 知识库（知识图谱）

- **数据源**：`data/knowledge/sources/discovery-report.csv`（桌面资料副本，6 条需求假设 / 27 条事实引用，去重后 25 个事实节点）+ `config.yaml`（六角色、主流程六步、四类红线、七份资料清单）。
- **节点类型**：`hypothesis` 6、`fact` 25、`role` 6、`flow_step` 6、`redline` 29、`document` 7、`policy` 1，共 **80 节点 / 88 边**。
- **边关系**：`cites`（假设→事实）、`owned_by`（假设/流程→角色）、`next`（流程顺序）、`includes`（合规中心→红线）、`applies_to`（合规中心→假设）、`based_on`（假设→资料）。
- **构建**：`python scripts/build_knowledge.py`，原子写入 `data/knowledge/graph.json`，不改动任何原始资料。
- **查询**：`query_graph` 按 id/type/label/text/source_ref 匹配，做一跳邻居与关联边扩展，上限来自 `knowledge.max_query_results`。
- **红线**：`knowledge.forbid_as_behavior_evidence=true`；`rule_refs` 只生成 `knowledge_refs`，标注「规则引用，不构成学生行为证据」；harness 用例验证「只有规则引用、无 fact_refs」的建议仍被 `NO_EVIDENCE` 拦截。
- **边界**：知识库解释规则与流程，不存储学生个人信息，不参与自动判断学生能力。

## 8. ⑤ 本地部署（Ollama）

配置段（全部在 `config.yaml`，代码零硬编码）：

| 字段 | 当前值 | 作用 |
| --- | --- | --- |
| `model.enabled` | `false` | 默认离线规则建议；置 `true` 启用本地模型 |
| `model.provider` | `ollama` | 按 provider 分发：`ollama` / `openai_compatible` |
| `model.base_url` | `http://127.0.0.1:11434/api/generate` | 生成接口地址 |
| `model.health_url` | `http://127.0.0.1:11434/api/tags` | 健康探测地址 |
| `model.model_name` | `qwen3.5:4b` | 本地模型名 |
| `model.api_key_env` / `api_key_required` | `LSA_MODEL_API_KEY` / `false` | 本地无需密钥；需要时只从环境变量读 |
| `model.think` | `false` | 关闭思考输出，避免 thinking 占满 token 导致正文为空 |
| `model.timeout_seconds` / `max_tokens` / `temperature` | `60` / `128` / `0` | 超时、长度、采样 |
| `model.offline_fallback` | `false` | 模型失败直接报错；置 `true` 才在文本中显式标注「不是模型输出」 |
| `paths.prompt_template` | `data/prompts/suggestion.txt` | 运行时提示词模板，见 `docs/提示词.md` |

启动与自测：

```
ollama serve                         # 本机服务已在 11434 运行
ollama pull qwen3.5:4b               # 首次部署时拉取模型
python scripts/verify_local_model.py # 离线 / 失败 / 显式降级 / 真实生成，4 类路径
# 启用模型：把 config.yaml 的 model.enabled 改为 true
python server.py                     # 之后 /api/v1/cycle 的建议会标注 model_provider=ollama:qwen3.5:4b
```

调用链：`build_suggestion` → 规则文本 `rule` → `_build_prompt` 注入模板 → `_call_model` 按 provider → `_call_ollama`（`stream=false`、`think=false`）→ `_check_model_text` 文本级审查 → `review_suggestion` 结构化审查 → 人工确认队列。模型输出**不写 `fact_refs`**，证据始终来自识别结果。

## 10. 风险与待确认

1. `X-Actor` / `X-Role` 是演示级身份，生产必须接组织认证，否则岗位可伪造。
2. 自写 YAML 子集解析器只支持「键: 值」「键:」「键: [a, b]」，注释必须独占一行；改块列表或行内注释会拒启。
3. `repeat_window_hours=24`、`timeout_hours=8`、漏单分母与响应起算点仍为待核实口径，试点前须按业务编号跑两周基线。
4. 模型输出已过「字段黑名单 + 文本禁止词 + 结构化证据审查」，但仍须人工确认；不能把审查通过理解为可自动触达。
5. 思考型模型若不设 `think=false`，`response` 可能为空并报 `MODEL_ERROR`；旧版 Ollama 不支持 `think` 参数时需升级或改用非思考模型。
6. 真实 LMS / 群聊 / 辅导工单接口尚未接入，目前是只读样本源 + 带时间戳快照降级。
7. 黑板上的 `www.examcoo.com` / `考试酷` / `1139295` 属于考试平台与考场编号，需本人登录操作，系统不代登录、不代答题、不代提交。
